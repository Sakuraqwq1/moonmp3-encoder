# 验收与初审自查

> 本文件按官方验收 9 条和初审实际尺度维护。状态以仓库当前 `main` 为准，不把“计划实现”写成“已经完成”。

结论：**形式项 7/9 满足，但第 3、7 条是核心项，当前不能作为完整 MP3 编码器通过验收。** 0.1.1 是结构里程碑，不是最终验收版本。

## 二、阶段 1 完成前的初审红线

以下任一未满足，不提交初审：

- [ ] 真实 PCM 能编码成非静音 MP3，独立解码器能还原。
- [ ] 主频/声道/长度正确，不只是“有声音”。
- [ ] 单声道和立体声都通过，`mp3dump --strict` 无 warning。
- [ ] 帧网格仍是精确 128 kbps CBR，`verify.py structure` 不回归。
- [ ] 有至少一组可复现的 SNR 数据和对应 fixture。
- [ ] README 更新为真实编码命令，不再写着“主数据全为零”。
- [ ] 申报书由本人撰写，功能声明集中为单章节，明确边界和非目标。
- [ ] 重新确认生态中仍无 MP3 编码器，引用可查的搜索证据。

## 三、阶段 2 完成后的初审门槛

- [ ] 正弦 SNR ≥ 20 dB，音乐样本 SNR ≥ 15 dB；数值附参考文件和解码器。
- [ ] 单/双声道、`1152±1`、静音、满幅、瞬态、长音频矩阵通过。
- [ ] 至少两个独立解码器结果一致（延迟对齐后比较长度和波形）。
- [ ] reservoir 连续多帧不越界，长序列不产生爆音。
- [ ] 核心用例进入 `moon test`，评委一条命令能看到通过。
- [ ] 对比同码率 LAME 的体积和 SNR，差距如实写入 README。
- [ ] 发布 0.2.0 或更高版本，CI 全绿，仓库与发布包一致。

## 四、验收期保持开发

初审通过后不需要再交表，但仓库要保持真实演进：

- 每周有意义的提交，不集中 dump。
- 新功能必须同时有测试和验证命令。
- 不改已发布标签；修复用补丁版本。
- 验收前用全新目录拉取一次，按 README 从零跑通。
